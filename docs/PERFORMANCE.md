# PERFORMANCE.md — 性能开销实测

**简体中文** · [English](en/PERFORMANCE.md)

> 口径：**v1.2.13**，PHP 8.3.6 CLI，单核容器，OPcache 关，`salt` 固定（同 salt 产物可逐字节复现）。
> 本文只描述**当前版本**的行为；所有数字都可用第 2 节的命令重跑。
> 绝对毫秒只在同机对比时有意义，**倍数**可跨机参考。

---

## 1. 一句话结论

| 档位 | 真实项目页面（TP8 `/shop/calc`） | 纯计算微基准 | 定位 |
|---|---:|---:|---|
| `min` | **1.02×**（3.18 → 3.25 ms） | 1.0× | 无反调试 / 无壳 / 无 `eval`，可全站铺开 |
| `low` | **15.8×**（→ 50 ms） | — | token 级全套 + 多层壳，请求路径可用 |
| `mid` | **44.6×**（→ 142 ms） | — | 同上 + 状态机 / 蜜罐 / 防篡改，后台与内部系统可用 |
| `high` | **74.8×**（→ 238 ms） | **10.1×** | 单层 VM；只压核心文件，或前置缓存 |
| `max` | **83.6×**（→ 266 ms） | **10.8×** | 单层 VM + 全套壳，核心文件 / 授权校验 |
| `ultra` | **246×**（→ 782 ms） | **50.4×** | 嵌套 VM，离线任务与关键算法片段 |

四条要点：

1. **`high` 起步才有 VM**，它的开销与「执行语句数」成正比，与文件大小基本无关。
2. **`max` 与 `high` 的纯计算开销几乎相同**（10.8× vs 10.1×）：页面上的 1.1 倍差距全在**每请求一次的壳层解码与完整性校验**上，不在业务代码。
3. **`ultra` 比 `high` 贵 3.3 倍以上**：嵌套 VM + 多层状态机，解释器套解释器。它只适合低频入口。
4. **`logic` 层不再按迭代数收费**（v1.2.13）：循环里的恒等式积木被搬到循环外，只算一次。见第 5 节。

## 2. 测量方法（可复现）

```bash
# A) 真实项目：TP8 整站 25 个 PHP 文件（app/ + route/ + config/，vendor 不混淆）
cp -a longtmp/tp8demo/tp8 /tmp/tp8src
php entry.php --input=/tmp/tp8src --output=/tmp/tp8_low -low --whitelist-dirs=vendor --salt=tp8v1213
php8.3 -S 127.0.0.1:9202 -t /tmp/tp8_low/public          # 每档独立副本 + 独立 SQLite
curl -s -o /dev/null -w '%{time_total}\n' 'http://127.0.0.1:9202/index.php/shop/calc'

# B) 纯计算微基准（VM 档）
php8.3 tests/perf_bench.php --runs=5 --levels=high,max,ultra --workload=tests/perf_workload_vm.php

# C) 循环不变量外提：开关对照（第 5 节）
php entry.php --input=/tmp/bench4.php --output=/tmp/on.php  -low --no-loop-fold
php entry.php --input=/tmp/bench4.php --output=/tmp/off.php -low --no-loop-fold --no-logic-loop-hoist
```

指标口径：

| 指标 | 含义 |
|---|---|
| 冷启动总耗时 | `php <产物>` 的墙钟中位数，含 PHP 进程启动（本机 CLI ≈ 24.3 ms） |
| 纯计算耗时 | 负载脚本内部 `hrtime` 自测，**不含**进程启动与解码 |
| 解码/编译开销 | 冷启动 − 纯计算 − 空脚本基线 ≈ 壳层解密 + `eval` 编译（每请求一次） |
| 峰值内存 | `memory_get_peak_usage(false)`（精确字节；`true` 会按分配块取整，几 MB 内的差异看不出来） |
| 页面延迟 | `curl` 的 `time_total`，15 轮**交替采样**取中位数（六档轮流跑，消除顺序漂移） |

所有变体与原生**必须输出同一校验和**，否则该行作废——语义被破坏时性能数字没有意义。
本次六档的 `/shop/calc` 响应体与原生**逐字节相同**。

## 3. 真实项目：ThinkPHP 8 整站（25 文件，含 ORM、缓存、中间件、验证器、事件）

单端点 `/shop/calc`（价格计算：查库 → 折扣 → 分桶 → 汇率 → JSON 输出），15 轮交替采样。
体积是整个站点目录（含原样拷贝的 `vendor`，约 4.2 MB）：

| 档位 | 中位数 | p90 | 相对原生 | 体积 |
|---|---:|---:|---:|---:|
| 原生 | 3.18 ms | 3.42 ms | 1.00× | — |
| `min` | 3.25 ms | 3.83 ms | **1.02×** | 3.9 MB |
| `low` | 50.4 ms | 55.3 ms | **15.8×** | 4.6 MB |
| `mid` | 141.7 ms | 149.9 ms | **44.6×** | 5.3 MB |
| `high` | 237.9 ms | 324.8 ms | **74.8×** | 7.0 MB |
| `max` | 265.8 ms | 271.8 ms | **83.6×** | 7.3 MB |
| `ultra` | 782.0 ms | 791.6 ms | **246×** | 15 MB |

读数要点：

- `min` 的 1.02× 是「编译期字面量折叠 + 改名」的净效果，几乎与原生同速。
- `low` / `mid` 的固定成本主要是**每请求一次的解码链**（`low` 2 层 eval + gz，`mid` 5 层 eval + 防篡改 + 状态机），与业务量无关。
- `high` 的 p90 明显高于中位数（324 vs 238）：VM 首次加载要编译字节码，冷请求更贵；OPcache 打开后这条曲线会平得多。
- `ultra` 的 15 MB 体积本身就是负担（磁盘 + 每次 `include` 的 IO），只适合离线。

## 4. 纯计算微基准：VM 档

负载：整数/字符串密集计算 + 生成器，校验和固定。5 轮中位数：

| 变体 | 纯计算 | 相对原生 | 峰值内存 | 解码/编译 | 构建耗时 |
|---|---:|---:|---:|---:|---:|
| 原生 | 1.3 ms | 1.00× | 0.64 MB | — | — |
| `high` | 12.6 ms | **10.1×** | 6.44 MB | 23.1 ms | 1.8 s |
| `max` | 13.5 ms | **10.8×** | 7.14 MB | 26.0 ms | 1.9 s |
| `ultra` | 63.0 ms | **50.4×** | 13.84 MB | 63.8 ms | 1.7 s |

- VM 的代价是**解释执行**：每条语句一次 dispatch。10× 与「每条语句折成 10 条 VM 指令」的量级一致。
- `ultra` 是 VM 套 VM：外层解释器要解释内层的解释循环，所以是 `high` 的 5 倍而不是 2 倍。
- 内存涨幅主要来自**字节码常量池 + 符号表**，与源码规模正相关，与运行时长无关。

## 5. 循环不变量外提（v1.2.13）

### 5.1 问题

`logic` 层把每个字面量改写成**函数调用形态的恒等式**：

```php
// 源码
for ($i = 0; $i < 20000; $i++) { $acc += strlen('abcdefghijklmnop'); }

// logic 处理后（循环每跑一轮，这两处就真算一遍）
for ($i = 0; $i < ((strlen(sha1('Q5KtYDi'))*500)-0); $i++) {
    $acc += strlen(hex2bin('616263').str_rot13('def'));
}
```

语义上是纯值，但**求值次数被循环放大了**：20000 轮 = 20000 次 SHA-1 + 20000 次字符串解码。
这就是 `low` / `mid` 在循环密集业务上比原生慢两个数量级的原因。

### 5.2 做法

`logic` 在改写之前先跑一遍**循环不变量外提**（LICM，loop-invariant code motion）：

1. 静态估算每个循环的迭代数（`for` 的初始值/边界/步长、`while` 前面那句赋值、`foreach` 的数组字面量 / `range()`）；
2. 迭代数 **> 阈值（默认 20）** 时，把「每轮都会求值」的区域里的字面量整体搬到循环语句**之前**，各用一个临时变量承接；
3. 循环条件与循环体里只剩变量引用，积木只在循环外算一次。

```php
// 外提后
$_90962bb54 = (((strlen(sha1('qfOBSxw'))*500)^0) + (in_array(1,[])?0:0));   // 只算一次
for ($i = (0); ((($i) <=> ($_90962bb54)) === -1); $i++) { $acc += $i; }
```

### 5.3 实测

负载：20000 轮，迭代数来自运行时（**不可**构建期折叠），循环体含 1 个字符串字面量 + 1 个比较。
7 轮中位数：

| 构建 | 运行耗时 | 相对原生 |
|---|---:|---:|
| 原生 | 0.2 ms | 1× |
| `low`（默认，外提开） | **4.1 ms** | 20× |
| `low`（`--no-logic-loop-hoist`） | **669 ms** | 3345× |
| `mid`（默认，外提开） | **3.7 ms** | 18× |
| `mid`（`--no-logic-loop-hoist`） | **506 ms** | 2530× |

**外提把每轮 25~34 µs 的积木开销压回 0**，剩下的 4 ms 是壳层解码（每请求一次，与迭代数无关）。
关闭外提时，每多跑一轮就多付一次哈希/解码——迭代数越大差距越夸张。

### 5.4 边界

外提只搬**字面量**（纯值、无副作用、无求值顺序依赖）。以下一律原样保留：

- 常量上下文：`const` / 参数默认值 / 属性默认值 / `case` 标签 / `#[…]` / `declare(...)`；
- 跳转层级操作数（`continue 2` / `break 3` 必须是整数字面量）；
- 函数体、闭包、箭头函数、类体内部——那些字面量**不**在循环里逐轮执行，搬出去会让函数体引用一个它看不见的变量；
- 迭代数 ≤ 阈值的小循环——为省几微秒引入一个变量不划算，保留原混淆形态；
- 迭代数估不出来的循环（`while (true)`、`while ($row = f())`）——按「大循环」处理，一律外提。

循环体是单语句、或循环前一个 token 不是语句边界（`else`、无花括号的 `if`）时，整段会用 `{ … }` 包起来，
避免前置赋值被 `else` / `if` 吸附走。

**关闭方式**：`--no-logic-loop-hoist`；调阈值：`--logic-loop-threshold=N`（0 = 所有循环都外提）。
六档预设与逐壳层 `logic` 变换默认全部开启。

## 6. 开销归因：钱花在哪个开关上

| 开关 | 量级 | 说明 |
|---|---|---|
| `shell:vm` | **数量级（10~50×）** | 唯一随执行语句数增长的开关；函数/方法调用是最贵的操作 |
| `logic`（`--logic-intensity`） | **≈ 0**（v1.2.13 起） | 字面量积木被外提到循环外，只算一次；短循环（≤ 20 轮）保留原形态，代价可忽略 |
| `shell:gz` / `shell:eval` / `shell:anti_*` | **每请求固定 15~50 ms** | 解码 + 完整性校验，与业务量无关 |
| `--vm-junk` | +20% 左右 | 垃圾指令是**真执行**的，不是跳过 |
| `morph` / `keychain` / `builtinReplace` / `probe` / `fakeFog` | 运行期 ≈ 0 | 只加体积与构建时间，性价比最高的一档 |
| `constfold` | **负开销** | 构建期把字面量算完，运行期这段计算彻底消失 |
| `funcsplit` | +0.1~0.3 µs / 次调用 | 把内联语句换成一次函数调用；`level=3` 落在热循环里可测量 |
| `var` / `func` / `class` 改名 | ≈ 0 | 纯静态替换 |

`--vm-super-isa`：同版本内开/关的差异落在 15 轮采样的噪声带内（±1.5 ms 墙钟）。
它减少的是 dispatch 次数，但复合处理器仍要逐条解码子指令，省下的分派被抵消。
定位是**抗分析 + 零代价**，不要指望提速。

## 7. 已知性能特性与规避

1. **解码是每请求一次**：无 OPcache 时 `eval` 的代码不进字节码缓存。QPS 高时务必开 OPcache（`--opcache` 预热），否则每请求都要重新解密 + 编译外层壳。
2. **`ultra` 只适合低频入口**：嵌套 VM 让纯计算到 50×、页面到 246×，产物 15 MB。单文件核心算法可用，整站不要用。
3. **VM 档下用户函数被编译为字节码**，不再是 PHP 函数：`function_exists()` / 字符串回调由 VM 内部解析；依赖反射遍历用户函数的代码请用 `low` / `mid`。
4. **生成器 / 大数组在 VM 下内存更高**：微基准峰值 6.4 MB vs 原生 0.6 MB（`high`），`ultra` 到 13.8 MB。
5. **整站混淆的函数名唯一化**：`logic` 注入的 `__mod_*` 积木经 `module_link` 内联后，函数名带**文件派生段**（`__ml<层><文件>_<名>`），多文件项目不会互相 `Cannot redeclare`。同一份源码同 salt 可复现。
6. **循环密集的自研算法**：`logic` 已不再按迭代数收费，但 `funcsplit`（level 3）和 `statemachine` 仍会。这类代码优先用 `high`（VM 在编译期折叠常量）或对热函数加白名单。
7. 想关掉某个拖慢的开关：`--no-logic-loop-hoist`、`--no-vm-super-isa`、`--vm-junk=0`、`--no-vm-cpool`、`--no-newline-poison`、`--no-shell-shield`（最后一项最影响体积与解码时间）。

## 8. 选型建议

| 场景 | 建议 | 理由 |
|---|---|---|
| 高频 Web 接口、内部系统 | `low` 或 `mid` | 16~45 倍，绝对延迟仍是几十毫秒；`logic` 已不再拖累循环 |
| 自研算法 / 循环密集代码 | `high` | VM 在编译期折叠常量，10× 纯计算；比 `mid` 的 45× 页面开销更可控 |
| 对外分发的组件 / SDK | `high` | 单层 VM，代价可控，抗分析足够 |
| 授权校验、计费核心片段 | `max`（只压该文件） | VM + 全套壳，把代价限制在少量文件 |
| CLI 批处理 / 离线任务 | `max` / `ultra` | 不在乎运行时，追求最强保护 |
| 框架项目（ThinkPHP / Laravel） | 直接用预设 | 六档与原生逐字节等价，属性名/参数名默认保留 |

**分层混搭**最实用：核心文件 `max`，其余 `mid`。

```bash
php entry.php --input=app/service/PriceCalculator.php \
    --output=dist/service/PriceCalculator.php --level=max --salt=$SALT

php entry.php --input=app/controller --output=dist/controller --level=mid --salt=$SALT
```
