# PERFORMANCE.md — 性能开销实测

**简体中文** · [English](en/PERFORMANCE.md)

> 口径：PHP 8.3.6 CLI，单核容器，OPcache 关，`salt` 固定（同 salt 产物可逐字节复现）。
> 本文只描述**当前版本**的行为；所有数字都可用第 2 节的命令重跑。
> 绝对毫秒只在同机对比时有意义，**倍数**可跨机参考。

---

## 1. 一句话结论

| 档位 | 真实项目页面（TP8 `/shop/calc`） | 纯计算微基准 | 定位 |
|---|---:|---:|---|
| `min` | **1.05×**（3.14 → 3.29 ms） | 0.8× | 无反调试 / 无壳 / 无 `eval`，可全站铺开 |
| `low` | **18.3×**（→ 57.5 ms） | — | token 级全套 + 多层壳，请求路径可用 |
| `mid` | **36.6×**（→ 115 ms） | — | 同上 + 状态机 / 蜜罐 / 防篡改，后台与内部系统可用 |
| `high` | **89.5×**（→ 281 ms） | **3.0×** † | 单层 VM；只压核心文件，或前置缓存 |
| `max` | **75.4×**（→ 237 ms） | **2.9×** † | 单层 VM + 全套壳，核心文件 / 授权校验 |
| `ultra` | **258×**（→ 811 ms） | **3.8×** † | 嵌套 VM，离线任务与关键算法片段 |

> † `high`/`max`/`ultra` 的「纯计算」一列量的是**当前默认路径**：状态机层生成的分派
> `switch` 让这些文件走「不透明载荷嵌套」（源码加密后交 VM 执行，不走字节码），
> 所以倍数只有 3~4×。**纯字节码执行要贵一到两个数量级**（同一负载 24× 冷启动 /
> 约 450× 纯计算）。两条路径的差别、成因与后续计划见第 4 节。

四条要点：

1. **`high` 起步才有 VM**，它的开销与「执行语句数」成正比，与文件大小基本无关。
2. **`max` 与 `high` 的纯计算开销几乎相同**（2.9× vs 3.0×）：页面上的差距全在**每请求一次的壳层解码**上，不在业务代码。`max` 反而比 `high` 略快，是因为两条路径的壳链长度不同，这一段固定成本并不随档位单调递增。
3. **`ultra` 比 `high` 贵 1.3 倍左右**：外壳更多、载荷分片更细。它只适合低频入口。
4. **`logic` 层不按迭代数收费**：循环里的积木换成运算符级恒等，运行期零指令。见第 5 节。

## 2. 测量方法（可复现）

```bash
# A) 真实项目：TP8 整站（app/ + route/ + config/ 混淆，vendor 原样拷贝）
php entry.php --input=longtmp/tp8demo/tp8 --output=/tmp/tp8_low -low \
    --whitelist-dirs=vendor --salt=tp8v14
# 入口引擎只产出 .php 产物，非 PHP 资源（.env / .tpl / 静态文件 / runtime 库）需原样补齐，
# 或用一键脚本 other/thinkphp8-build.php（它自带这一步）
php8.3 -S 127.0.0.1:9202 -t /tmp/tp8_low/public          # 每档独立副本 + 独立 SQLite
curl -s -o /dev/null -w '%{time_total}\n' 'http://127.0.0.1:9202/index.php/shop/calc'

# B) 纯计算微基准（VM 档）
php8.3 tests/perf_bench.php --runs=5 --levels=high,max,ultra --workload=tests/perf_workload_vm.php

# C) 循环密集代码：注入形态对照（第 5 节）
php entry.php --input=/tmp/bench6.php --output=/tmp/on.php  -low --no-loop-fold
php entry.php --input=/tmp/bench6.php --output=/tmp/off.php -low --no-loop-fold --no-logic-loop-light
```

指标口径：

| 指标 | 含义 |
|---|---|
| 冷启动总耗时 | `php <产物>` 的墙钟中位数，含 PHP 进程启动（本机 CLI ≈ 25 ms） |
| 纯计算耗时 | 负载脚本内部 `hrtime` 自测，**不含**进程启动与解码 |
| 解码/编译开销 | 冷启动 − 纯计算 − 空脚本基线 ≈ 壳层解密 + `eval` 编译（每请求一次） |
| 峰值内存 | `memory_get_peak_usage(false)`（精确字节；`true` 会按分配块取整，几 MB 内的差异看不出来） |
| 页面延迟 | `curl` 的 `time_total`，21 轮**交替采样**取中位数（六档轮流跑，消除顺序漂移） |

所有变体与原生**必须输出同一校验和**，否则该行作废——语义被破坏时性能数字没有意义。
本次六档的 `/shop/calc` 响应体与原生**逐字节相同**（184 字节，sha1 `c87187d0f3ff`）。

## 3. 真实项目：ThinkPHP 8 整站（含 ORM、缓存、中间件、验证器、事件）

单端点 `/shop/calc`（价格计算：查库 → 折扣 → 分桶 → 汇率 → JSON 输出），21 轮交替采样。
体积是整个站点目录（含原样拷贝的 `vendor`）：

| 档位 | 中位数 | p90 | 相对原生 | 体积 |
|---|---:|---:|---:|---:|
| 原生 | 3.14 ms | 3.43 ms | 1.00× | 4.7 MB |
| `min` | 3.29 ms | 3.62 ms | **1.05×** | 4.7 MB |
| `low` | 57.5 ms | 58.9 ms | **18.3×** | 5.3 MB |
| `mid` | 115.1 ms | 119.1 ms | **36.6×** | 5.4 MB |
| `high` | 281.1 ms | 286.9 ms | **89.5×** | 6.9 MB |
| `max` | 236.9 ms | 244.6 ms | **75.4×** | 7.7 MB |
| `ultra` | 811.1 ms | 845.2 ms | **258×** | 18 MB |

读数要点：

- `min` 的 1.05× 是「编译期字面量折叠 + 改名」的净效果，与原生同速、体积不变。
- `low` / `mid` 的固定成本主要是**每请求一次的解码链**（`low` 2 层 eval + gz，`mid` 5 层 eval + 防篡改 + 状态机），与业务量无关。
- `high` / `max` 的成本分两块：壳层解码（固定）与字节码解释（随语句数增长）。p90 与中位数接近，说明缓存预热后曲线较平。
- `ultra` 的 18 MB 体积本身就是负担（磁盘 + 每次 `include` 的 IO），只适合离线。

## 4. 纯计算微基准：两条 VM 路径

负载：整数/字符串密集计算 + 生成器，校验和固定。5 轮中位数（`tests/perf_bench.php`）。

### 4.1 默认路径：不透明载荷嵌套

| 变体 | 纯计算 | 相对原生 | 峰值内存 | 解码/编译 | 构建耗时 |
|---|---:|---:|---:|---:|---:|
| 原生 | 1.0 ms | 1.00× | 0.64 MB | — | — |
| `high` | 3.1 ms | **2.97×** | 3.93 MB | 13.4 ms | 974 ms |
| `max` | 3.1 ms | **2.91×** | 4.49 MB | 15.2 ms | 1,008 ms |
| `ultra` | 4.0 ms | **3.78×** | 10.14 MB | 45.2 ms | 864 ms |

这条路径下字节码只做「解码 + `_PHPRUN` 执行」，业务语句仍在 PHP 引擎里跑，
所以倍数只有 3~4×：贵的是每请求一次的**壳层解码**（13~45 ms）和内存。

### 4.2 字节码路径：贵到什么程度

同一份负载改用裸 `--vm`（不经状态机层）构建，业务语句被编译成 VM 字节码逐条解释：

| 变体 | 冷启动总耗时 | 纯计算（反推） | 相对原生 |
|---|---:|---:|---:|
| 原生 | 21.8 ms | 1.0 ms | 1.00× |
| 字节码 VM | **490 ms** | ≈450 ms | **≈450×** |

「纯计算」由冷启动减去进程启动（19~22 ms）与壳层解码（约 15 ms）反推。每条语句一次
dispatch，循环体越碎越吃亏；这条路径只该出现在少量核心文件上。

### 4.3 为什么 `high` 默认落在 4.1 那条路径（已知限制）

VM 编译入口有一条保守守卫：`case` 标签必须是编译期字面量。链路是——
`statemachine` 生成分派 `switch` → 排在它后面的 `number` 层把标签改写成 `(N^0)` 表达式
→ 守卫判定「标签不是字面量」→ 整文件退回 `vmPayloadNest`。构建日志里看得见
（同一原因整站只提示一次；逐文件明细用 `--verbose`）：

```
[WARN] shell:vm 未做字节码编译，改走不透明载荷嵌套（…）：case 标签为关键字名
```

`compileSwitch()` 本来就是把每个标签按**比较链**编译的，并不需要常量，放行表达式标签
在编译层面可行；但放行之后立刻会撞上第二个问题：`funcsplit` / `module_link` 注入的
函数声明被状态机包进了 `case` 体，而 VM 没有「运行期注册函数」的指令（`DEF_FUNC`），
依旧只能整文件回退。两件事**一起**改才是完整解，已列为 v1.3.1 首项。

本版**不改变**这一行为，只把它从静默的 `info` 变成按原因去重的 `warn`：
保护强度是产品承诺的一部分，不该藏在日志级别里。

## 5. 循环密集代码：`logic` 层怎么收费

### 5.1 问题

`logic` 的常规积木是**函数调用形态**（`strlen(sha1('…'))*N`、`base64_decode(…)` 链）。
语义上是纯值，但求值次数会被循环放大：

```php
for ($i = 0; $i < 20000; $i++) { $acc += strlen('abcdefghijklmnop'); }
```

放进循环体就会被跑 20000 次；迭代数越大，代价越夸张。

### 5.2 做法

改写之前先静态估算每个循环的迭代数（`for` 的初值/边界/步长、`while` 前那句赋值、
`foreach` 的数组字面量 / `range()`）。超过阈值（默认 **20**）的循环里，逐轮求值的区域
（`for` 的条件与步进、`while`/`do-while` 的条件、循环体）中的字面量改成**运算符级恒等**：

```php
// 循环内：编译期常量折叠，运行期零指令
for ($_i = ((0-0)); $_i < $_n; $_i++) {
    $_acc += strlen('abcdefgh' . 'ijklmnop');   // 拼接在编译期完成
    if ('y' . 'es' === 'y' . 'es') { $_acc += ((1-0)^(00)); }
}
```

源码里没有裸字面量、没有可一眼读出的常量，但也没有任何函数调用被迭代放大。
循环之外、以及 ≤ 阈值的小循环，仍然使用完整积木。

### 5.3 实测

负载：20000 轮，迭代数由运行时决定（**不可**构建期折叠），循环体含 1 个字符串字面量 +
1 个恒真比较。7 轮中位数：

| 构建 | 运行耗时 | 相对原生 |
|---|---:|---:|
| 原生 | 0.20 ms | 1× |
| `low`（默认） | **3.10 ms** | 15.5× |
| `low`（`--no-logic-loop-light`） | **40.8 ms** | 204× |
| `mid`（默认） | **3.11 ms** | 15.6× |
| `mid`（`--no-logic-loop-light`） | **61.0 ms** | 305× |
| `high`（载荷嵌套执行） | **0.54 ms** | 2.7× |

默认形态下 20000 轮只花 3.1 ms（≈0.15 µs/轮，主要是壳层一次解码与 `strlen` 调用本身）；
关掉轻量注入，每轮都要重算积木，迭代数越大差距越夸张。
v1.3.0 把积木本身从 `strlen(md5('…'))`（约 0.3 µs/次）换成十进制分块 + 位掩码
（约 0.02 µs/次），所以「默认」那一行比 v1.2.14 又便宜了约 18%。

### 5.4 边界

只处理**纯值字面量**。以下一律原样保留：

- 常量上下文：`const` / 参数默认值 / 属性默认值 / `case` 标签 / `#[…]` / `declare(...)`；
- 跳转层级操作数（`continue 2` / `break 3` 必须是整数字面量）；
- 函数体、闭包、箭头函数、类体内部——那些字面量**不**在循环里逐轮执行；
- 迭代数 ≤ 阈值的小循环——保留完整积木，混淆密度更高；
- 迭代数估不出来的循环（`while (true)`、`while ($row = f())`）——按「大循环」处理。

字符串层同一口径：`StringEncoder` / `StringRuntimeAssembler` 复用同一套循环判定
（`LoopScanTrait`），大循环内的字符串不做 XOR + 解码，保留字面量或编译期拼接。

**关闭方式**：`--no-logic-loop-light`；调阈值：`--logic-loop-threshold=N`（0 = 所有循环都按大循环处理）。
六档预设与逐壳层 `logic` 变换默认全部开启。

## 6. 开销归因：钱花在哪个开关上

| 开关 | 量级 | 说明 |
|---|---|---|
| `shell:vm` | **3~4×（载荷嵌套）／最高约 450×（字节码）** | 唯一随执行语句数增长的开关；函数/方法调用是最贵的操作 |
| `logic`（`--logic-intensity`） | **≈ 0** | 循环内只放运算符级恒等（编译期折叠、运行期零指令）；循环外是一次性的取值 |
| `shell:gz` / `shell:eval` / `shell:anti_*` | **每请求固定 15~60 ms** | 解码 + 完整性校验，与业务量无关 |
| `--vm-junk` | +20% 左右 | 垃圾指令是**真执行**的，不是跳过 |
| `morph` / `keychain` / `builtinReplace` / `probe` / `fakeFog` | 运行期 ≈ 0 | 只加体积与构建时间，性价比最高的一档 |
| `constfold` | **负开销** | 构建期把字面量算完，运行期这段计算彻底消失 |
| `funcsplit` | +0.1~0.3 µs / 次调用 | 把内联语句换成一次函数调用；`level=3` 落在热循环里可测量 |
| `var` / `func` / `class` 改名 | ≈ 0 | 纯静态替换 |

`--vm-super-isa`：开/关的差异落在 21 轮采样的噪声带内（±2 ms 墙钟）。
它减少的是 dispatch 次数，但复合处理器仍要逐条解码子指令，省下的分派被抵消。
定位是**抗分析 + 零代价**，不要指望提速。

## 7. 已知性能特性与规避

1. **解码是每请求一次**：无 OPcache 时 `eval` 的代码不进字节码缓存。QPS 高时务必开 OPcache（`--opcache` 预热），否则每请求都要重新解密 + 编译外层壳。
2. **`ultra` 只适合低频入口**：页面 258×、产物 18 MB。单文件核心算法可用，整站不要用。
3. **VM 档下用户函数被编译为字节码**，不再是 PHP 函数：`function_exists()` / 字符串回调由 VM 内部解析；依赖反射遍历用户函数的代码请用 `low` / `mid`。
4. **生成器 / 大数组在 VM 下内存更高**：微基准峰值 3.9 MB vs 原生 0.6 MB（`high`），`ultra` 到 10.1 MB。
5. **整站混淆的函数名唯一化**：`logic` 注入的 `__mod_*` 积木经 `module_link` 内联后，函数名带**文件派生段**（`__ml<层><文件>_<名>`），多文件项目不会互相 `Cannot redeclare`。同一份源码同 salt 可复现。
6. **循环密集的自研算法**：`logic` 已不按迭代数收费，但 `funcsplit`（level 3）和 `statemachine` 仍会。这类代码优先用 `high`（VM 在编译期折叠常量）或对热函数加白名单。
7. **入口引擎只产出 `.php`**：整站构建时非 PHP 资源（`.env` / `.tpl` / 静态文件 / runtime 库）要自己补齐，或用一键脚本（它会自动复制）。缺 `.tpl` 会让 ThinkPHP 的异常页渲染失败——正常路径看不出来，只有报错时才炸。
8. **`case` 标签让文件退到「载荷嵌套」**：见 4.3。构建日志（`warn`，按原因去重）会点名这类文件；想确认某个文件到底走没走字节码，用 `--verbose` 看逐文件明细。
9. 想关掉某个拖慢的开关：`--no-logic-loop-light`、`--no-vm-super-isa`、`--vm-junk=0`、`--no-vm-cpool`、`--no-newline-poison`、`--no-shell-shield`（最后一项最影响体积与解码时间）。

## 8. 选型建议

| 场景 | 建议 | 理由 |
|---|---|---|
| 高频 Web 接口、内部系统 | `low` 或 `mid` | 18~37 倍，绝对延迟仍是几十毫秒；`logic` 不拖累循环 |
| 自研算法 / 循环密集代码 | `high` | 常量在编译期折掉，纯计算 3×；比 `mid` 的页面开销更可控 |
| 对外分发的组件 / SDK | `high` | 单层 VM，代价可控，抗分析足够 |
| 授权校验、计费核心片段 | `max`（只压该文件） | VM + 全套壳，把代价限制在少量文件 |
| CLI 批处理 / 离线任务 | `max` / `ultra` | 不在乎运行时，追求最强保护 |
| 框架项目（ThinkPHP / Laravel） | 直接用预设 | 六档与原生逐字节等价，属性名/参数名默认保留 |

**分层混搭**最实用：核心文件 `max`，其余 `mid`。

```bash
php entry.php --input=app/service/PriceCalculator.php \
    --output=dist/service/PriceCalculator.php --level=max --salt=$SALT

php entry.php --input=app/controller --output=dist/controller --level=mid --salt=$SALT
```
